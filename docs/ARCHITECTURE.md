# Архитектура

## Слои

```
KAPL (app target)          composition root: AppDelegate, AppEnvironment
 ├── KAPLUI                AppKit-окна щита, режим киоска, строка меню + SwiftUI-содержимое
 ├── KAPLSystem            адаптеры macOS: LocalAuthentication, IOKit, системная блокировка
 └── KAPLCore              домен: автомат состояний, координатор, порты (протоколы)
```

Весь код, кроме composition root, лежит в локальном Swift-пакете `Packages/KAPLKit`. Направление зависимостей задано таргетами пакета:

- `KAPLCore` ничего не импортирует из AppKit;
- `KAPLSystem` и `KAPLUI` зависят только от `KAPLCore` и не знают друг о друге;
- только `AppEnvironment` знает все конкретные типы и связывает их.

Благодаря этому логику безопасности можно тестировать без реального Mac, а системный механизм (например, способ аутентификации) заменяется без изменений в остальных слоях.

## Поток управления

```
 ввод на щите ─► ShieldController ─► LockCoordinator.requestUnlock()
                                            │
                                   LockReducer (чистая функция)
                                   phase' + [effects]
                                            │
              ┌─────────────────────────────┼──────────────────────────┐
         shield.render(phase)        effects → порты              логирование
                                   (auth, sleep, system lock)
```

- **`LockReducer`**: все решения по безопасности в одной чистой функции `(phase, event) → (phase', effects)`. Покрыта тестами.
- **`LockCoordinator`**: `@MainActor @Observable`; передаёт события автомату, рисует фазу на щите и выполняет эффекты через порты.
- **Порты** (`Ports.swift`): `Authenticating`, `SleepPreventing`, `SystemLocking`, `ShieldPresenting`.
- **Щит рендерится декларативно**: `render(phase)` идемпотентен, щит сам решает, что показать, исходя только из фазы.

## Фазы

| Фаза | Щит | Запрет сна | Выход |
|---|---|---|---|
| `unlocked` | нет | нет | `lockRequested` |
| `locked` | да | да | ввод → `authenticating` |
| `authenticating` | да | да | успех → `unlocked`, отмена → `locked`, ошибка → счётчик |
| `coolingDown` | да | да | таймер → `locked` |
| `escalated` | нет, работает системная блокировка | **да** | пользователь разблокировал macOS → `unlocked` |

## Ключевые решения

1. **Режим киоска вместо глобального event tap.** Ввод блокируется через `NSApplication.presentationOptions` (Dock, меню, ⌘Tab, Force Quit и выход из сессии отключены) и локальный монитор событий. Accessibility и Input Monitoring не нужны, а системный диалог Touch ID работает штатно. Ограничение: схема работает, только пока приложение активно, поэтому потеря фокуса считается *нарушением* (breach).
2. **Эскалация вместо «аварийного выхода».** Нарушение, недоступная аутентификация или слишком много неудачных попыток переводят Mac в **системную блокировку macOS**. Она тоже не останавливает процессы, а запрет сна сохраняется до разблокировки macOS. Сомнения всегда решаются в пользу большей защиты, и способа заблокировать себе доступ к Mac нет.
3. **Разблокировка только через аутентификацию.** Горячая клавиша может включить блокировку, но не снять её.
4. **Ничего постоянного.** Power assertions и параметры киоска живут вместе с процессом: если приложение упало или его убили, Mac возвращается в обычное состояние. Автозапуска в заблокированном состоянии нет.
5. **Пароль не проходит через приложение.** `LAPolicy.deviceOwnerAuthentication`: Touch ID с резервным системным запросом пароля, который рисует сама macOS.
6. **Системная блокировка через приватный API** (`SACLockScreenImmediate` из login.framework): публичного API для этого нет. Это допустимо при распространении через Developer ID, но в Mac App Store не пропустят. Если символ исчезнет, `lockNow()` вернёт `false`, и щит просто останется поднятым.

## Распространение

Developer ID + нотаризация, без App Sandbox: полноэкранный киоск и приватный API с песочницей и правилами Mac App Store несовместимы. Hardened Runtime уже включён в настройках таргета. Для релиза нужно указать `DEVELOPMENT_TEAM` и подписывать сертификатом «Developer ID Application».

## Куда расти

- `LockMode.monitor` / `.transparent`: `ShieldContentView` пока для всех режимов показывает Privacy (безопасный вариант по умолчанию).
- Горячая клавиша (Carbon `RegisterEventHotKey`, Accessibility не требуется).
- Мониторинг питания и батареи (`IOPSNotificationCreateRunLoopSource`) как ещё один порт в Core.
- CLI `kalock` и хуки Claude Code для Monitor Mode.
- Watchdog-процесс, который при падении приложения включает системную блокировку.
- Локализация (String Catalog, ru/en).
